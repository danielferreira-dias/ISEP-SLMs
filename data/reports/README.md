# Dataset reports

These files are generated by:

```bash
.venv/bin/python -m src.data_pipeline.pipeline
```

Version 1 records the initial 13-class candidate analysis. Version 2 records
the 20-class expansion. Version 3 is the current 21-class analysis, adds
`drug_eruption`, indexes the excluded Dermnet Kaggle mirror for auditability,
integrates SkinDisNet as an external-only source, and adds demographic and
subgroup-support reporting.

The primary current reports are:

- `source_disease_inventory_v3.csv`: source labels, canonical labels, mapping
  status, and per-source counts;
- `all_source_disease_coverage_v3.csv`: totals for every canonical source
  label, including labels outside benchmark scope;
- `disease_coverage_v3.csv`: coverage of the 21 active benchmark classes using
  taxonomy contributors only;
- `included_diseases_v3.yaml`: the 21 classes that pass preliminary support
  thresholds;
- `out_of_scope_source_labels_v3.csv`: source labels retained for accounting
  but excluded from the benchmark taxonomy.
- `demographic_availability_v3.csv`: group-level metadata availability for all
  source rows and benchmark-mapped rows;
- `subgroup_coverage_v3.csv`: group and image support for reportable
  demographic subgroups, by dataset and disease.
- `duplicate_pairs_v3.csv`: exact, perceptual, and source-lineage pair
  evidence with Hamming distance, label agreement, and review status;
- `duplicate_groups_v3.csv`: connected duplicate components and their
  dataset, disease, inclusion, and conflict summaries;
- `duplicate_summary_v3.csv`: per-dataset hashing coverage, duplicate counts,
  exact exclusions, and cross-dataset overlap.
- `perceptual_review_queue_v3.csv`: unresolved perceptual candidates in
  deterministic review order.

The review queue priorities are mapped-label conflicts, internal-to-external
overlaps, other cross-dataset overlaps, and then pHash distances 0, 2, and 4.
Reviewed false positives are removed from the queue through
`configs/datasets/duplicate_review.yaml`.

The subgroup report omits non-informative values such as `unknown`,
`other_or_unspecified`, and `prefer_not_to_answer` from metric-eligible groups.
Their absence remains visible through the availability and missingness counts.
Measurement systems are not pooled.

SkinDisNet appears in the source inventory, demographic-availability report,
and subgroup-support report. It does not contribute to
`disease_coverage_v3.csv` or `included_diseases_v3.yaml`, because those
artifacts are intentionally calculated only from taxonomy contributors.

Perceptual matches are candidates rather than confirmed duplicates. Pending
rows already share a leakage group, so a candidate relationship cannot cross
internal splits. The frozen release is stored under
`data/benchmarks/visual_top_k_v1/`. Model-ready Parquet datasets,
release-specific reports, and integrity metadata are separated into
`datasets/`, `reports/`, and `release/`, respectively.
